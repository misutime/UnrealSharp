## 0.1 复核记录（师傅，第二轮 · 方案评审）

**判定：有条件可用。** 方向与需求边界一致——不引入默认上下文、不承诺让后台入口（`Task.Run`/计时器/第三方回调/终结器）变安全，而是靠"**运行期边界拒绝 + 编译期提示 + 规范**"把问题显性化；这一目标可达成，不需要完整线程安全体系。
但**当前文字不能直接实施并宣称"已生效"**：有几处"安全豁免/覆盖范围"写得比实际机制更强。下列条目中标注「已改」的已同步修正到对应章节；其余按待办处理。

**阻塞项（P0，实施前必须闭合）**

1. **`GameThreadDispatcher.RunAsync` 只保证"传入的同步委托内部"在游戏线程**：实现是 `TaskCompletionSource(RunContinuationsAsynchronously)`（`GameThreadDispatcher.cs:30-49`），`await` **之后**的代码不保证在 GT。
   ⇒ 分析器豁免范围只能是**委托体**；**必须禁止并诊断 `RunAsync(async () => …)`**（签名是 `Action`，async lambda 会变成 `async void`）。【已改 §3.4；§1 新增第 7 条；规范同步修正】
2. **W3 候选 B"覆盖属性读写"目前不成立**（已核实反例）：`UnrealArrayBase<T>.Count => NativeBuffer->ArrayNum`、`NativeArrayBuffer => NativeBuffer->Data` 直接读原生内存、**不经过 marshaller**；`Clear/Add/Insert/RemoveAt` 走 `Bind_FArrayProperty`（不在原漏斗集合内）。且 `BlittableMarshaller<T>` 只是通用内存拷贝，**无法区分"UObject 属性内存"与"临时缓冲"**。
   ⇒ 先做覆盖矩阵（标量 / bool 位域 / 对象引用 / struct / 容器 / 委托 / 函数参数与返回值 / 手写 interop）；检查必须位于**首次解引用之前**；B 的口径改为"原生函数漏斗 + 原生视图与容器入口 + 必要的定点生成器修改"，并**明确写出受保护集合**。【已改 §3.3】
3. **Tier A 与 `ThreadChecks=0` 自相矛盾**：§0/§3.2 说 Tier A 含 Shipping 始终拒绝，§6 回退却允许关闭全部检查。
   ⇒ Tier A **不可由运行时开关关闭**；开关只控制 Tier B 与日志详细度；回退 = "降到 A"；`[ThreadSafe]` 不得绕过 Tier A。【已改 §6】
4. **W2 入口清单不完整、错误协议未闭合**（已核实四处）：
   - `Bind_UObject.cpp:181-209` 的 `StaticLoadClass` / `StaticLoadObject`（加载包、可能建对象）无任何守卫；
   - `Bind_FTypeBuilder.cs:14` **先分配强句柄再调原生**，拒绝时句柄归属未定义；
   - `FunctionExporter.cs:1181-1183` 生成的 specialization **把原生返回值直接写进缓存**，拒绝会缓存"失败结果"；
   - `CSFieldName.h:54-56` 模板 `ResolveField<T>()` = `CastChecked<T>(ResolveField())`，而 `CastLogError` 是 `UE_LOGF(LogCasts, Fatal)`（引擎 `Templates/Casts.cpp:8-12`，**所有配置都生效**）⇒ 我们把 `ResolveField` 改成"可返回 nullptr"之后，**模板包装仍会 Fatal**。
   - 错误协议分两类：**指针返回**入口（原生返零 + 托管在"缓存 / 解引用 / 参数尺寸查询"**之前**判零抛异常）；**void 入口**（托管前置检查只保证"受支持包装"的线程契约，不能让裸原生调用自动获得可捕获异常）。"不改 ABI"可以，但不能承诺"任何原生拒绝都变成可捕获托管异常"。【已改 §3.2、§1 第 3 条】
5. **分析器不得用方法名/标注当作安全证明**（已核实）：`ConfigureWithUnrealContext()` 的限制多于 world-bound——已完成的 `ValueTask` 直接返回、**不切线程**（`UnrealSynchronizationContext.cs:183-185, 225-229`）；构造要求有效 world（`:240-248`）；world 失效静默丢回调（`:276-281`）；接受 `NamedThread` 参数（不保证 GameThread）；非泛型 Task 重载不传播 fault（`:166-180`）。
   ⇒ US0015 豁免限定为"真实符号 + GameThread 参数"，并要求对同步完成 / 异步完成 / 取消与异常分别验证；不能证明的情形继续提示。【已改 §3.4】

**P1（发布前闭合）**

6. **W5 关机拒收要定义"交接"而非只置标志**：拒收发生在句柄分配前还是后；原生接受与关机之间的竞态如何定界；拒绝后的 Task 必须**明确完成为失败**；拒绝路径的**唯一 owner**（禁止双释放）；排队分支**执行时是否复核 GC/关闭状态**（`Bind_Async.cpp:46-50` 目前直接 `Invoke`，而"已排队"≠"已达安全时机"）。【已改 §3.5】

**建议砍掉 / 降级（控制成本，避免过度设计）**

- 砍掉 `[ThreadSafe]` 同时豁免运行期与分析器的整套机制；本轮改为"**内部安全 API 白名单 + 分析器定向抑制（须附理由）**"；
- 推迟线程身份缓存（先一次原生查询，测到热点再优化）；
- 推迟 `RunAsync(action, timeout)` 公共重载（超时后 action 仍可能迟到执行，语义更坏）；
- 不做全量 bind 调用点注入；但**不为"避免重生成"而拒绝必要的定点生成器修改**；
- 近期不开放 Shipping 动态打开 Tier B（开发包/Test 足以支撑本轮目标）；
- W1 只做"计数 + 首例 + 有限近期记录"（**有界存储**；`what` 是"操作类别"而非精确调用点）；
- **规范只保留一个权威文件**（`docs/C#脚本线程与引擎访问规范.md`），游戏工程放链接与短摘要，避免两份漂移。

## 0. 目标与非目标

**目标（本方案交付）**
1. 违规**能被开发人员看到**：编译期提醒（分析器）+ 开发期响亮失败（Tier B 注入）+ 违规计数/日志。
2. 违规**不会静默变成 UB/致命**：所有"建对象/注册类型/加载程序集/解析字段"入口在**所有配置（含 Shipping）**统一拒绝（Tier A）。
3. 规则**写下来并可持续执行**：规范文档 + CR checklist + 工具映射。

**明确的非目标（本轮不做）**
- ❌ **不做"默认回游戏线程"（原计划第 ④ 步）**：帧量化延迟、后台重活被搬上 GT、一旦有上下文则"GT 上阻塞等待"变成经典 self-deadlock、对现存项目是行为变更，且它管不到 `Task.Run`/计时器/第三方回调/终结器等无上下文可捕获的路径。决策记录见规范 §10。
- ❌ **不做生成器对每一个 bind 调用点的全量注入**（作为可选后续，见 W3 候选 A）。
- ❌ 不做静态元数据初始化改造（原计划第 ⑤ 步）。

**已接受的前提**：无法在代码/逻辑层面完全消除该类问题；目标是把"偶发致命/静默 UB"变成"**开发期可见 + 运行期可控失败**"。

## 3. 详细设计

### 3.1 W1：诊断与可观测性

**原生**（`Bind_UCSManager` + `CSManager`）：

```cpp
// 一次往返拿全状态（诊断快照，不是锁：三个位不保证原子一致）
// bit0 = IsInGameThread(), bit1 = IsGarbageCollecting(), bit2 = IsGarbageCollectingAndLockingUObjectHashTables()
int GetEngineCallState();
int GetThreadViolationCount();     // 违规计数（std::atomic<int32>）
```

- `EngineCallGuard.IsEngineCallSafe` 改为读 `GetEngineCallState()`；`EnsureEngineCallAllowed` 的异常消息带上三个位（用于**解释**拒绝原因，不是按需放宽守卫）。
- **日志节流（有界）**：按"操作类别（`what`）+ 线程"只打**一次**完整栈，之后只 `+计数`；记录要**有界存储**（线程与字符串都是动态的），命令只回放"最近 N 条"。措辞用"**操作类别节流**"，不要承诺精确调用点去重（同一 marshaller 的多个调用点会合并）。
- **一次违规只计一次**：托管先拒绝、原生拒绝、外层异常记录三者不得各加一次。
- **控制台命令**：`unrealsharp.ThreadViolations [N]` → 打印计数 + 最近 N 条（线程 id / 状态位 / 类别）。
- **CVar**：`unrealsharp.ThreadChecks` **只控制 Tier B 与日志详细度**；**Tier A 不可关闭**（见 §6）。默认：Shipping `1`，Development/Test/Debug/Editor `2`。
- 自动化用例用**执行前后计数差值**断言，而不是要求全进程恒为 0。
- **本轮不做线程身份缓存**（先用一次原生查询；测到热点再优化）——缓存正确性依赖"运行时已初始化、GT 身份稳定、生命周期不变"，不是 `[ThreadStatic]` 本身保证的。

### 3.2 W2：Tier-A 边界收口（始终开启，含 Shipping）

补齐已知遗漏入口（都满足"会创建对象 / 加载包 / 改反射"）：

| 入口 | 位置 | 后果 |
|---|---|---|
| `RegisterManagedType_Native` | `Source/UnrealSharpCore/Private/Binds/Bind_FTypeBuilder.cpp` | 走 `CSManagedAssembly::RegisterManagedType` → 类型编译器建 `UClass`/`UStruct` |
| `CreateNativeFunctionCustomStructSpecialization` | `Source/UnrealSharpCore/Private/Binds/Bind_UFunction.cpp` | `NewObject<UFunction>` + 新建 `FStructProperty` |
| `StaticLoadClass` / `StaticLoadObject` | `Source/UnrealSharpCore/Private/Binds/Bind_UObject.cpp:181-209` | 加载包、按名取类/对象，可能建对象；**目前无任何守卫** |
| `FCSFieldName::ResolveAssembly` / `ResolveField` 调用方审计 | 全 `Source/`（**含模板包装**） | 语义已从 `check` 变为"返回 nullptr"；`CSFieldName.h:54-56` 的 `ResolveField<T>()` 用 `CastChecked`，空指针命中 `UE_LOGF(Fatal)` ⇒ 必须逐点判空 |
| 生成调用方的判零 | `Source/UnrealSharpManagedGlue/**/FunctionExporter.cs:1181-1183` | specialization 返回值**直接入缓存**；拒绝会缓存"失败结果" ⇒ 必须"判零后再缓存" |

**错误协议**（分两类，不改 ABI）：
- **指针返回入口**：原生拒绝返回零；托管侧必须在**缓存 / 解引用 / 参数尺寸查询之前**判零并抛异常。
- **void 入口**（如 `RegisterManagedType_Native`）：托管**前置检查**保证"受支持包装"的线程契约；它**不能**让裸原生调用自动获得可捕获异常。
- 句柄所有权要闭合：`Managed/UnrealSharp/UnrealSharp/Interop/Bind_FTypeBuilder.cs:14` **先分配强句柄再调原生** ⇒ 检查必须在分配**之前**，并明确"原生拒绝时句柄由谁释放"。
- 口径：可以承诺"**受支持的托管包装**能获知线程拒绝"，**不能**承诺"任何原生拒绝都变成可捕获托管异常"；全局违规计数不是单次调用的结果通道。

**为什么不做"给入口加状态返回值"（ABI 改造）——以及 `nullptr` 的语义分层**

判定不是"改不改 ABI"一刀切，而是每类入口问三件事：**① 谁需要知道失败？② `nullptr` 是否已被占用为合法语义？③ 改签名的波及面有多大？**

| 入口 | 返回值 | `nullptr` 是否合法语义 | 采用的做法 |
|---|---|---|---|
| `CreateNativeFunctionCustomStructSpecialization` | 指针 | **否**（没有"合法空"） | 保留指针 + **调用点判零后再缓存**（修 `FunctionExporter` 生成代码：先判零，零则抛，不入 `Dictionary`） |
| `StaticLoadClass` / `StaticLoadObject` | 指针 | **是**（"资源未找到"就是 null） | 保留指针 + **用托管前置检查消歧**：前置检查通过 ⇒ null 归因"未找到"；前置检查不通过 ⇒ 直接抛异常、**根本不调原生** |
| `RegisterManagedType_Native` | `void` | — | 托管**前置检查 + 拒绝时抛异常**（不调原生）；原生守卫只作最后一道防线，且**必须在任何状态修改之前**检查返回（不留半完成状态） |
| `LoadAssemblyByPath` / `GetNativeField` / `CreateNewObject`（上一版已实现） | 指针 | 否 | 保持现状 |

**不做全局 ABI 改造的三条理由**：① 托管前置检查已经在**受支持路径**上把"违规"变成"调用前抛异常"，再改签名的**边际收益很小**；② 真正需要补的是**调用点缺口**（`FunctionExporter` 缓存零值、`Bind_FTypeBuilder` 句柄分配顺序、`StaticLoad*` 缺守卫、模板 `ResolveField<T>()`），不是返回值形态；③ **本代码库特有的风险**：原生插件与生成的 glue（含用户工程 `Intermediate/**`）必须严格同步，改签名后一旦 glue 过期就会出现**互操作签名不匹配**——比"静默失败"更难查（本插件已有"生成物过期/漏编"的历史坑）。
**将来若确实需要精确失败原因**：**新增** `Try…` 形式入口（如 `bool TryRegisterManagedType(..., out reason)`）作为增量 API，而不是改旧签名——旧调用点不受影响，也不必强制重生成全部 glue。

### 3.3 W3：Tier-B 开发期注入（"响亮失败"）

**先修正一个覆盖承诺**：候选 B **不能**宣称"覆盖属性读写"。已核实的反例：`Managed/UnrealSharp/UnrealSharp/UnrealArray.cs:51-56` 的 `Count => NativeBuffer->ArrayNum`、`NativeArrayBuffer => NativeBuffer->Data` **直接读原生内存**，不经过任何 marshaller；`Clear/Add/Insert/RemoveAt` 走 `Bind_FArrayProperty`（不在原漏斗集合内）；`Get()` 也是**先读 Count/缓冲地址**，元素 marshaller 处的检查已经晚于首次原生访问。另外 `BlittableMarshaller<T>` 只是通用内存拷贝，**无法区分"UObject 属性内存"与"独占临时缓冲"**，无差别加检查会波及纯数据路径。

**修正后的做法**：
1. **先出覆盖矩阵**：标量 / bool 位域 / 对象引用 / struct / 容器（Array/Map/Set）/ 委托 / 函数参数与返回值 / 手写 interop，逐项标注"入口、检查点、是否已有"。
2. **检查必须位于首次解引用之前**。
3. B 的定义改为"**原生函数漏斗 + 原生视图与容器操作入口 + 必要的定点生成器修改**"：漏斗至少含 `Bind_UObject`（`InvokeNativeFunction/...StaticFunction/...WithParams`、`StaticLoadClass/StaticLoadObject`、`CreateNewObject`）、`Bind_UFunction`、`Bind_UClass`、`Bind_UScriptStruct`、`Bind_UCoreUObject`、`Bind_FArrayProperty` 等容器操作；容器视图（`UnrealArray/UnrealMap/UnrealSet` 的 `Count`/索引/增删）需要各自入口或定点注入。
4. **明确写出"受保护集合"**：不再声称全量覆盖；生成代码不报分析器**不等于**全部由 Tier B 覆盖。
5. **性能策略**：Tier B 默认只在开发期（Development/Test/Debug/DebugGame/Editor）开启；GC 位不可缓存。
6. **错误协议**：`UnrealSharpThreadViolationException`（含线程、状态位、建议写法）；按操作类别只打一次完整日志，计数继续。

**候选 A（可选后续）：生成器注入** —— 位置 `Source/UnrealSharpManagedGlue` 与 `Managed/UnrealSharp/UnrealSharp.GlueGenerator`；覆盖最全但会重生成 `Intermediate/UnrealSharp/UHT/**`（本机约 2.2 万文件）。**不为"避免重生成"而拒绝必要的定点生成器修改**（例如容器视图与生成访问器）。**已获授权（决策 9）**：W3 允许为"容器视图 / 生成访问器"做**定点**注入，接受因此重生成部分 glue 文件（仍不做全量 bind 注入）。

**例外出口（修订）**：**本轮不引入 `[ThreadSafe]`**（它需要把"原始调用者成员"传播到通用漏斗，复杂且容易扩大豁免）。改为"**内部审核的固定安全 API 白名单 + 分析器定向抑制（必须附理由）**"；无论哪种方式都**不得绕过 Tier A**。

### 3.4 W4：分析器（编译期，`US0015+`）

位置：`Managed/UnrealSharp/UnrealSharp.Analyzers`（**该项目已存在并已通过 `UnrealSharp.Shared.props:41` 挂到所有用户工程**），新文件 `ThreadAffinityAnalyzer.cs` + 复用现有 `AnalyzerStatics`；新规则登记进 `AnalyzerReleases.Unshipped.md`。

| ID | 检测（**能可靠做到的范围**） | 默认严重级 | 修正要点 |
|---|---|---|---|
| `US0015` | 同一方法体内，某次 `await` **之后**的**直接**引擎成员访问（基于操作树/局部控制流，**不按文本顺序**） | Warning（CI 可升 Error） | **豁免只能是"把工作放进 `RunAsync` 的同步委托内部"**；`await RunAsync(...)` **之后**的调用方续体不保证在 GT；`ConfigureWithUnrealContext()` 不是无条件豁免（见下）；嵌套 lambda、后续 await、分支都要处理 |
| `US0016` | 传给 `Task.Run` / `ThreadPool.QueueUserWorkItem` / `new Thread` / `Timer` / `ContinueWith` 的 lambda 或可解析局部函数/方法组体内出现引擎访问 | Warning | `PeriodicTimer` 构造**不收回调**（要盯 `WaitForNextTickAsync` 所在异步循环）；`AsParallel()` 本身不收操作 lambda（要盯后续 ParallelEnumerable 算子）；显式 scheduler / 间接 delegate 记为**明确局限** |

| `US0018` | 真正 Task/ValueTask 的阻塞 API（符号识别，不按 `.Result`/`.Wait()` 名字） | 初期 Info，稳定后 Warning | 文案写"**潜在阻塞风险**"而非"已经死锁"；`[UClass]` 普通方法不保证在 GT |
| `US0019` | 终结器（`~Ctor`）体内出现引擎成员访问 | Warning | 经普通 helper 间接触碰是**已知漏报**（本轮不做全程序调用图） |

**"引擎成员访问"的判定（决定误报率，务必保守）**
1. 以**真实程序集 / 符号身份**为主，不能只按命名空间 `UnrealSharp.*`（同一命名空间里也有纯托管工具与数据运算）；
2. 用户类型上带 `[UProperty]` / `[UFunction]` 的成员；以及继承自引擎绑定基类**且带标注**的成员；
3. 建对象 API 的**类型识别**可复用现有 `AnalyzerStatics`；但注意 `UObjectCreationAnalyzer.cs:74-101` 的 `US0007–US0011` 检查的是"用 `new` 创建 UObject"这种**创建方式**，**不是** `NewObject` 的线程合法性 —— 不能复用其安全结论；
4. **不报**：UObject 派生类上**未标注**的普通字段/属性；`[UStruct]` 的**纯值拷贝**（已脱离引擎的类型快照）也不必然碰引擎；
5. 规范必须写明"**不报 ≠ 安全**"；`GeneratedCodeAnalysisFlags.None` ⇒ 生成代码不报，**不等于**它已被 Tier B 覆盖。

**`ConfigureWithUnrealContext()` 的真实限制（豁免条件必须写清）**：构造要求有效 world（`UnrealSynchronizationContext.cs:240-248`）；world 失效静默丢回调（`:276-281`）；已完成的 `ValueTask` 直接返回、**不切线程**（`:183-185, 225-229`）；接受 `NamedThread` 参数（**不保证**是 GameThread）；非泛型 Task 重载不传播 fault（`:166-180`）。
⇒ 它**不是**"与入口线程、完成状态无关的切回 GT 原语"，**不能**被推荐为"后台线程首次进入引擎"的通用工具；US0015 只对"真实符号 + GameThread 参数"豁免，并要求对同步完成 / 异步完成 / 取消与异常分别验证。

**例外出口（修订）**：本轮**不引入 `[ThreadSafe]`**（通用漏斗不知道原始调用者成员，需要额外传播或 ambient scope，复杂且容易扩大豁免）；用"**内部审核的固定安全 API 白名单 + 分析器定向抑制（必须附理由）**"。`[GameThreadOnly]` 可作为将来标记自研 wrapper 的契约，首轮非必需。

**决策记录：当初为什么想到这两个标注、为什么本轮不引入**

| 标注 | 原设想的语义与用途 | 本轮不做的理由 |
|---|---|---|
| `[ThreadSafe]` | 声明"该成员任意线程可调用" ⇒ **分析器不报 + 运行期 Tier-B 跳过**。动机是给**误报**留出口（例如纯数据的 `FVector` 运算、临时缓冲的 marshalling 在后台线程） | ① 运行期注入点是**通用漏斗**（原生 bind 入口 / marshaller），**不知道原始调用者成员**——要兑现它必须额外做 ambient scope 或逐调用点传播，复杂且容易把豁免范围放大；② 它是一条**静默豁免通道**：标错就等于悄悄关掉守卫，正是我们要防的失败模式；③ 真正线程安全的成员应由**我们**在注入层按符号白名单排除，而不是由调用方标注 |
| `[GameThreadOnly]` | 反向声明"只能 GT 调用"：分析器在已知后台上下文里报点，同时作为**自研 wrapper** 的契约文档 | 核心规则靠**符号身份**（引擎绑定类型/成员）判定即可，不需要标注；它只对"你自己写的、内部会碰引擎的 C# wrapper"有增量（保守判定对未标注成员不报）。属**可选增强**，不是达成需求的前提 |

- **本轮替代方案**：内部安全 API 白名单 + 分析器定向抑制（须附理由）+ `#pragma` / `.editorconfig` 调严重级。
- **什么时候值得再引入**：① 分析器在合法后台路径上的误报多到"pragma 变噪声"；② 开始维护覆盖引擎调用的自研 C# wrapper 库、希望它们被标记；③ 要在 CI 上强制"GT-only 契约"。引入红线：`[ThreadSafe]` **不得绕过 Tier A**，标注必须有依据并进 CR。
- 两者都是**纯增量 API**，以后加不破坏兼容 ⇒ **"现在不加"没有代价**。

**迁移策略（避免一次性把现有工程 build 打红）**：先按 Warning 发布 + 提供 `.editorconfig` 片段（`dotnet_diagnostic.US0015.severity = warning|error`）；对现有代码跑一次基线扫描（W6），按报点数量决定何时提升为 Error。

**已定（决策 7）：默认 `Warning`，试用一段时间无问题后再升 `Error`。** 升级判据（可量化，避免"感觉没问题就升"）：
1. 基线扫描的**每一条报点都被分类处置**——要么改成合规写法，要么定向抑制并附理由，**不存在"未分类"项**；
2. 连续 **N 个开发周期 / 若干次完整构建**内**没有新增未处置报点**（N 建议 2~4 周或一个里程碑，由项目定）；
3. 合法后台路径（纯数据、临时缓冲等）的**误报已被白名单或规则收窄解决**，不是靠堆 `#pragma` 压下去的。
升级动作 = 只改 `.editorconfig` 的严重级（**不动代码**），可按目录/工程随时回退；也可对**新目录/新模块先行设 `error`**（新代码零容忍，老代码平滑）。

**测试**：新增 `Managed/UnrealSharp/UnrealSharp.Analyzers.Tests`（Roslyn `Microsoft.CodeAnalysis.*.Testing` + xUnit）。每条规则配正例/反例，**必须包含**：`await RunAsync(...)` **之后**的续体访问（应报）、`RunAsync(async () => …)`（应报）、方法组 / 分支 / 同名普通 API、以及 `ConfigureWithUnrealContext()` 的同步完成与取消路径。

### 3.5 W5：dispatcher 最小生命周期（按"**交接**"定义，而非只置标志）

> ⚠️ **本节要点已被 §10.6 的"可执行交接状态机"取代**（提交前拒收 / 分配后未接收 / 已接收待执行 / 执行成功 / 执行时拒绝，各规定 Task 结果与句柄唯一 owner）；实施以 §10.6 为准，本节保留为背景。

- **拒收时机**：模块 Shutdown 置位后，`RunAsync` 在**句柄分配之前**拒绝，并**明确把 Task 完成为失败**（`TrySetException`），不静默挂起。
- **竞态定界**：明确"原生接受"与"关机置位"的先后语义（一旦接受，就必须完成或明确失败）。
- **唯一 owner**：正常路径由 `FCSManagedDelegate::Invoke(bDispose = true)` 释放；**拒收路径另定唯一释放方**，禁止双释放。
- **排队分支**：`Bind_Async.cpp:46-50` 目前直接 `Invoke`；需明确"**到达执行时是否复核 GC/关闭状态**"——"已排队" ≠ "已达安全时机"（要么执行时复核，要么给出实跑证据）。
- **超时告警**：Development 下对"已派发但长时间未执行"打 Warning（含计数与类别），**不自动杀任务**；告警不能只依赖已经停住的游戏线程（要有其它观测出口）。
- **本轮不做**：`RunAsync(action, timeout)` 公共重载（超时后 action 仍可能迟到执行，语义更坏）、完整取消与关机排空保证（记为残余风险）。

### 3.6 W6：规范与流程（**前置**，不是收尾）

- **只保留一个权威规范文件**：`docs/C#脚本线程与引擎访问规范.md`；游戏工程放**链接 + 短摘要**（不复制全文，避免两份漂移）。

### 9.5 错误契约（六类，冻结）

| 类别 | 契约 |
|---|---|
| 普通受支持托管入口 | **拒绝 + 抛专用异常** |
| 终结器 / 原生反向回调 | **拒绝，但异常不得逸出**；记录方式**不递归** |
| 已验证线程安全且生命周期成立的清理原语 | 才可**精确豁免**（逐个函数，禁止整类） |
| 生成代码静态构造 | 允许失败，但**接受"该已加载类型不可用且不重试"** |
| 显式 `Dispose`（GT 正常调用） | 可报告失败，不得留下"字段已清零、原生未释放"或析构重试态 |
| 从终结器/反向回调进入的 `Dispose` | **无异常逸出** |

**两个必须处理的反例**：① `UnmanagedCallbacks.cs:185-205`（`[UnmanagedCallersOnly]`）的 catch 在 `:202` 用 `StringMarshaller.ToNative` 写错误文本 → 走 `Bind_FString.Call*`；若守卫在同状态再次抛，**第二个异常会逸出原生回调边界** ⇒ 错误写回通道必须不经过"会被守卫拒绝的路径"，或自带兜底；② 同文件 `:228-258` 的 `Dispose`/`FreeHandle` 直接调 `IDisposable.Dispose()`，**无捕获**。
**插件自身被终结器调用的入口**：`Extensions/Core/Text.cs:71-87`、`NativeStructHandle.cs:27-41`、`StrongObjectPtr.cs:28-31/78-87`、`InstancedStruct.cs:50-58`、`StaticVars/WorldStaticVar.cs:34-37`、`GameStaticVar.cs:38-41/54-58`。
**事务性检查（不得中途拒绝）**：`TextMarshaller.ToNative`（`Text.cs:203 Release → :207 覆盖 → :208 AddRef`）必须在事务开始前拒绝；`RegisterManagedType` 在**分配强句柄前**检查 + 明确唯一 owner；specialization 拒绝值**不得入缓存**；`AddRef`/`Release` 成对语义要有约定。
**"宁可泄漏也不要 UAF"的边界**：只作**明确、有界、可诊断**的取舍；⚠️ **拒绝 delegate 解绑会留下指向托管回调的原生记录 = 悬空回调，不能当可接受泄漏**。
**开关语义**：`unrealsharp.ThreadChecks` 关闭只影响 Tier B 与日志详细度；**Tier A 永不关闭**；本轮冻结为"**改 CVar 需重启生效**"。

**P1/P2/P4 的边界（师傅第二轮/第三轮修正，必须一并冻结）**
- **R3 的结论是"目标缓冲独占不足以豁免随后经 `FProperty`/引擎源地址/带生命周期 payload 的操作"，不是"所有 `BlittableMarshaller` 调用都是引擎访问"**。该类本身只是裸内存拷贝：对**独占、有效的纯 POD 缓冲**调用它**可以完全不碰引擎**。
- 因此 P1 的口径为：**经元数据、引擎源地址或带生命周期 payload 的路径必须受保护；纯 POD 独占拷贝不是违规。** 通用 marshaller **无法自证内存来源** ⇒ 引擎访问检查应放在**有来源信息的调用边界**（生成访问器 P3 / 原生入口），纯数据内部原语不承诺自行辨别来源。
- P2 的标记不能只叫"是否临时缓冲"并据此放行：应是**经审核的"独占纯数据缓冲"路径**，且**不得豁免元素操作中的 A 入口**。
- **不能同时冻结"全局 P1 注入 + 纯数据不误拒 + P4 必定不需要"这三个承诺**：若"不修改引擎访问器"无法同时满足"首次访问保护"与"纯数据不误拒"，则**启用必要的定点修改（P4 局部）或明确缩小受保护集合**（写进残余）。

**豁免必须按函数符号，不得按类排除**：最小基础集合 = `CallIsOnGameThread`、`CallIsCollectingGarbage`、`CallGetEngineCallState`、`CallGetThreadRefusalCount`、`CallGetThreadBoundaryCatchCount`、`CallReportBoundaryCatch`、`Bind_FMsg.CallLog`、`Bind_Async.CallRunOnThread/CallRunOnGameThread/CallGetCurrentNamedThread`。（排除整个 `Bind_UCSManager` **过宽**：它还含对象/接口包装与世界查询。）这只是守卫/日志/派发的最小豁免，**不是最终线程安全白名单**；错误文本输出、启动绑定、清理仍需单独审计。
**性能**：先用缓存的 `static readonly bool`（Tier B 开关）短路，再走 **W1 已实现的** `GetEngineCallState()` 一次查询；只在违规时构造字符串；**同一个合法 GT 操作可能经过多个 P0/P1 检查 ⇒ 必须实测调用次数与热路径**（A 已检查的入口不应被 B 重复诊断，但 B 开关不得影响 A）。

### 9.8 确定性验证门（发布前必须做；不得拿工作编辑器试崩）

1. 终结器被拒**不使进程退出**（**独立子进程**）；
2. 反向回调报错时**错误写回不再抛**（§9.5 反例① 的回归）；
3. 正常 GT 创建后，**释放 / GC / PIE 结束 / 关闭**路径无新失败；
4. 强句柄、引用计数、缓存的**拒绝前后状态**一致；
5. 计数"一次拒绝只计一次" + "边界内捕获"独立计数（需故障注入钩子）；
6. 确定性 GC 状态用例（不靠概率命中）；
7. B 开关语义 + A 不可关闭（`ThreadChecks=0` 时 Tier A 仍拒绝）。

### 9.9 接受的残余（明确写入规范）

`Task.Run`/Timer/第三方回调/终结器/自建线程内部的用户代码（除非最终调用 `Call*` 被 P0 拒）；`unsafe` 裸指针与手工 `Marshal`；后台算值但不调原生的路径（**设计上不报**）；分析器覆盖不到者（反射/动态/第三方内部）；反向回调 `Invoke_*` 的参数解封方向；§9.2 审计的静态局限；Shipping 下 Tier B 关闭。
（W2/W3 全量注入的**冻结前提**：① W1 实测观测数据；② §10 的逐符号入口表；③ 师傅复核。**"逐入口表"以 §10 为准**。）

### 10.4 开关、计数与自依赖（师傅第 5 项）

1. **B 开关只取一次快照**：`unrealsharp.ThreadChecks` 在**启动时读取一次**并由统一入口暴露；**不得**每个 Bind 类首次触碰时各自懒取样（否则运行中改 CVar 会让冷/热类配置分裂），与"改 CVar 需重启生效"一致。
2. **新增自依赖符号按精确符号豁免**：`CallGetEngineCallState`、`CallGetThreadRefusalCount`、`CallGetThreadBoundaryCatchCount`、`CallReportBoundaryCatch`（W1 已加），以及 W3 将新增的"B 配置查询"。
3. **托管先拒绝时由谁计数**：`EngineCallGuard.EnsureEngineCallAllowed` 目前**只抛不记**（`EngineCallGuard.cs:49-65`）⇒ W3 必须规定**托管侧拒绝时调用专用计数入口**，不能指望"未被调用的原生守卫"计数。
4. **bootstrap 不经过自身守卫**（前提要写下来）：`NativeBinds.TryGetBoundFunction` 是手写函数指针调用（`UnrealSharp.Binds/BindsManager.cs:17-29`）；生成的静态构造先用它解析函数地址、再进入 `Call*` ⇒ 前提 = **绑定表已注册完成、查询期间不并发改表、清理前停止使用**。它不进 `Call*` 豁免名单，但属于启动前提。
5. **"每个入口只检查一次"不是本轮机制**：只冻结两条规则 —— ① 每个符号明确 A/B 归属，**A 的托管检查不受 B 开关影响**，P0 不为同一入口追加 B 诊断；② **一次拒绝只记一次 refusal**，边界 catch 另记 boundary-catch。合法路径保留多层检查并**实测调用次数**；**不得为去重删掉首次访问保护或原生防线**。

### 10.5 非逸出错误协议（师傅第 3 项：两个反例的"捕获后怎么办"）

- `UnmanagedCallbacks.cs:200-205`：**整个 catch 内的格式化、写回、日志**都放进"非逸出"协议 —— 主回调失败必须返回非零；错误文本是 **best-effort**；写回/日志再失败时允许保留原生已初始化的空错误文本（`CSFunction.cpp:95-101` 已构造空 `FString`），**不得改变失败返回值、不得再走会被守卫拒绝的诊断路径**。
- ⚠️ `CSFunction.cpp:108-115` 仍有 `bCrashOnException` 的显式 Fatal 策略 ⇒ "托管异常不逸出"**不等于**"所有设置下原生都不终止"；测试须显式关闭该策略，或另行规定线程违规是否区别处理（列入 §9.8 验证门）。
- `UnmanagedCallbacks.cs:228-258` 的 `Dispose`/`FreeHandle`：按 §10.3 的 owner 协议，不能只写"加 catch"。

### 10.6 W5 交接协议（师傅第 6 项，替换原则式表述）

`GameThreadDispatcher.RunAsync`（`GameThreadDispatcher.cs:30-49`）与原生 `RunOnGameThread`（`Bind_Async.cpp:37-50`）的**可执行状态机**：

| 状态 | 判定点 | Task 结果 | 句柄唯一 owner |
|---|---|---|---|
| 提交前拒收（开关/关机已置位） | 托管侧、**分配句柄之前** | **明确失败**（`TrySetException`） | 未分配 ⇒ 无 |
| 分配后未接收（原生拒收） | 原生入口 | **明确失败** | 托管释放（唯一 owner） |
| 已接收待执行 | 原生已入队 | 必完成或必失败 | 原生（`FCSManagedDelegate::Invoke` 默认释放） |
| 执行成功 | GT 执行完 | 成功 | 原生释放 |
| 执行时 GC/关闭拒绝 | GT 执行时复核（**不得跑用户 action**） | 走**独立失败完成通道** | 原生释放 |

补充约束：① 接收与关闭必须有**明确先后判定点**；② "已接收必完成/失败"与"不做完整关机排空"要一致 —— **有序关闭负责结算已接收任务并释放；强制退出不保证**；③ **ALC 卸载时不得保留会调用已卸载委托的任务**；④ 允许用新增内部 `Try…` 或专用完成回调实现，**不必改旧 ABI**。

### 10.7 验证门与残余的增补（师傅第 7 项）

**§9.8 增补用例**：合法操作**真实完成**（不能靠吞异常得到零 Error）；冷/热类型、缓存命中/未命中、CDO 已有/未有；**合法 null 与线程拒绝的区别**；**纯 POD 后台拷贝正例**；W5 五种交接状态 + 关闭竞态；**delegate 清理后再广播不得调用已释放回调**；B 启动配置固定且运行中改 CVar 不使冷/热类分裂；**强制原生拒绝**与**托管先拒绝**两条路径分别核对副作用与计数。故障注入必须**模拟 unsafe 状态以强制拒绝**，不得在真实 GC 中伪装 safe 后继续危险操作。

**§9.9 残余增补**：状态快照不是锁、**不能证明对象有效或跨 ALC 指针有效**；静态构造毒化；原生 `void`/合法 null 的结果通道局限；**有限且明确的清理残余**；`Task.Run` 等是**执行来源、不是自动绕过守卫的机制** —— 应写"无一般性线程证明，但调用受保护入口仍会被拒"，且要提 A/P1/P2/P3 而不只是 P0；"反向回调参数解封全部未保护"改为**逐路径列出已覆盖与剩余裸访问**（全局 P1 若实施，共用 marshaller 的反解封也会被检查）。

**分析器口径修正**：`解决方案.md` §3.4 与规范 §5 里"真实符号 + GameThread 参数"只是**必要条件**，**不是充分的 GT 证明**；无法证明同步完成分支也安全时，`US0015` 继续提示。

### 11.2 托管检查点的落点调整（**相对 §10.2 措辞的偏离，需复核**）

§10.2 把托管最早检查点写成"调用前检查 / 生成代码静态构造的调用前"。实测发现两件事，导致落点上移一层：

1. 这些入口的调用点大多在**生成代码**里（静态构造、`_GetSpecialization`、生成的 invoker），而生成它们的 UHT glue 生成器属 §9.7 **P4**（改一次全量重写 22,336 文件 + 全量重编）；
2. 在手写 C# 的 9 个调用点上逐个加检查，会随新调用点出现而再次漏。

**因此实现的机制是**：在 `delegate*` 字段上加属性 `UnrealSharp.Binds.GameThreadEntry`，由**内存源生成器**（`NativeCallbacksWrapperGenerator`）在生成的 `Call*` 包装**首行**发出 `EngineCallGuard.EnsureEngineCallAllowed("<符号名>")`，并在需要时对返回值判零/判负（`NoNullResult` / `NonNegativeResult`）。

- 证据：`Managed/UnrealSharp/UnrealSharp.Core/obj/Debug/net10.0/UnrealSharp.SourceGenerators/.../Bind_UClass.generated.cs`（`EmitCompilerGeneratedFiles=true` 落盘）——`CallGetDefault` 首行为 `EnsureEngineCallAllowed("GetDefault")`；`CallGetPropertyOffset` 为"检查 + `int result = …` + `EnsureNotNegativeResult`"。
- 为什么这仍满足"调用前"：检查位于**托管侧调用原生函数指针之前**，且这些入口的原生守卫也在**任何状态修改之前**，故不存在"半完成状态"。
- 为什么不需要碰 P4：源生成器属 `Managed/**`，改它只重编托管程序集，**不触发 glue 重写**（本轮 UBT 仅 4–7 个 action 即为证）。
- **A/B 独立**：该检查**不看** `unrealsharp.ThreadChecks`，B 开关关掉也仍然拒绝（§10.4.5）。
- **自依赖豁免**：未给 `CallGetEngineCallState` / `CallGetThreadRefusalCount` / `CallGetThreadBoundaryCatchCount` / `CallReportBoundaryCatch` / `CallRecordManagedRefusal` / `CallShouldRunManagedThreadSelfTest` 加属性，避免守卫递归自身（§10.4.2）。
- 仍然保留**手写调用前检查**的两处（属 §10.3 owner 约定，必须在分配之前）：`Bind_FTypeBuilder.RegisterManagedType`（`GCHandle.Alloc` 之前）、`ManagedObjectMarshaller.ToNative`（分配/覆盖旧 owner 之前）。

`void` 入口（`InvokeNativeStaticFunction`、`DirtyUnrealType`、`NotifyNewType`）**必须**用调用前检查：原生拒绝时静默返回，会让调用方以为"已执行"。

### 11.3 结果通道（为什么 `INDEX_NONE`，以及为什么不制造静默错值）

- 指针入口：拒绝=空。**有合法空的入口**（`FindManagedObject` / `StaticLoad*` / `LoadSynchronous` / `GetNativePropertyFromName`）靠**托管前置检查**消歧，托管侧拒绝会抛专用异常；**无合法空的入口**（`CreateNativeFunctionCustomStructSpecialization`）由包装**判零抛**，因此 `FunctionExporter.cs` 的 `_Specializations.Add` 不会缓存拒绝值（**不改 P4 生成器**）。
- 整数入口：拒绝=`INDEX_NONE`（负）。偏移量 0 是合法值、`ArrayDim` 不可能为负 ⇒ 负值只可能表示拒绝；`NativeProperty.Offset/Size/ArrayDim` 读到的负值会抛。`GetPropertyOffsetFromName` 的 `-1` 是"未找到"的**既有约定**，故该入口不判负。
- 为什么现在加负值是安全的（而不是把崩溃换成静默错位）：这些入口在**生成静态构造**里的调用，前面必有 `NativeReflectionHelper.GetNativeField`（`GeneratorStringBuilderUtilities.cs:168`），而它已带 W1 的前置检查；池线程到不了这些调用。该推理是"同线程内状态不可变"的推论，写入残余（§11.6）。

### 12.2 实现后的状态机（与 §10.6 逐行对应）

| 状态 | 判定点（实现） | Task 结果 | 句柄唯一 owner |
|---|---|---|---|
| 提交前拒收 | 托管侧、**`GCHandle.Alloc` 之前**（`_acceptingWork == false`） | `TrySetException` | 未分配 ⇒ 无 |
| 分配后未接收 | 原生 `TryRunOnGameThread` 返回 0（**引擎正在退出**） | `TrySetException` | **托管**：`callbackHandle.Free()` |
| 已接收待执行 | 原生已 inline 或已 `AsyncTask(ENamedThreads::GameThread, …)` | 必完成或必失败 | 原生（`FCSManagedDelegate::Invoke` 默认 `bDispose=true`） |
| 执行成功 | GT 上 `TryExecuteWorkItem` | `TrySetResult` | 原生释放 |
| 执行时拒绝 | GT 上复核 `_acceptingWork` 与 `EngineCallGuard.IsEngineCallSafe` | `TrySetException`，**不跑用户 action** | 原生释放 |

补充实现要点：
1. **句柄指向队列而不是调用方的委托**：交给原生的 `GCHandle` 是 `new Action(() => TryExecuteWorkItem(workId))`（队列自身所在程序集），调用方的 `Action` 只存在于队列的 `_pending` 表里，按 workId 查。这样**排队项不会把可卸载程序集钉住**，ALC 卸载后该项查不到 ⇒ 直接不执行（§10.6③ 的落地方式）。
2. **不静默挂起**：所有完成走 `TrySet*`；`TryExecuteWorkItem` 整体 `try/catch`，异常只落到 Task 上，**不逸出原生回调边界**（原实现用 `SetResult/SetException`，二次完成会抛进原生调用栈）。
3. **拒绝计数分档可查**：`RefusedBeforeSubmission` / `RefusedByNative` / `RefusedWhileRunning` / `HandedToNative`（隔离队列可读，自检据此断言）。
4. **`async void` 不参与**：`RunAsync(Action)` 语义不变（§1 第 1 条、§3.4 的豁免范围不受影响）。

### 12.3 确定性自检（新增，随 §11.4 的钩子一起跑）

`Managed/UnrealSharp/UnrealSharp/GameThreadWorkQueueSelfTest.cs`（在 `UnrealSharp` 程序集内，可读 `internal` 判定点）在**隔离队列**上逐条驱动，不做任何引擎调用：

| 用例 | 断言 |
|---|---|
| 关机后提交 | 任务立即 faulted、action **未执行**、`HandedToNative==0`、`RefusedBeforeSubmission==1` |
| 提交后关机（执行时拒绝） | 任务被结算为 faulted、`TryExecuteWorkItem` 返回 false、action **未执行**、`PendingCount==0` |
| 提交后按程序集丢弃 | `DiscardPendingForAssembly` 返回 1、任务 faulted、action **未执行**、`PendingCount==0` |
| 正常接收 | 在 GT 上 inline 执行 ⇒ 任务成功、action 已执行、`HandedToNative==1`、无任何拒绝计数 |

### 12.5 W5 残余（明确写入）

1. **插件级"有序关机"没有自动调用点**：`GameThreadDispatcher.Shutdown()` 已实现且被自检覆盖，但把它挂到插件关闭需要**新增原生→托管关机回调**（`FCSManagedCallbacks` 扩字段属 ABI 变更）。当前由两条路径代替：① 引擎退出时 `TryRunOnGameThread` **拒收新任务**（已接收未执行的任务随进程结束，属 §10.6② 的"强制退出不保证"）；② ALC 卸载前按程序集丢弃+结算（已接）。

### 15.2 错误协议与开关

- `UnrealSharpThreadViolationException : EngineCallRefusedException`（消息含线程 / 三个状态位 / 建议写法）；**每个类别第一次完整记日志并计数，之后只计数**；同时调 `RecordManagedRefusal`，让 Tier B 违规进入与 Tier A 相同的 `unrealsharp.ThreadViolations` 计数面。
- 开关：原生新增绑定 `IsTierBEnabled`（读启动快照，**Tier A 永不读它**）；托管 `TierBChecks.Enabled` 是 `static readonly`，并且**对"绑定缺失"免疫** —— 托管程序集可能先于原生 DLL 重建，此时无条件调用函数指针会在静态初始化期崩溃（本轮真实踩到：用户编辑器在跑时重建了托管侧）。缺失即视为"检查关闭"。
